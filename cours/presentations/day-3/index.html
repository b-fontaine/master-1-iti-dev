Git en équipe · quatre habitudes

Petites PR

Une PR annonce une seule chose : elle se démontre et se vérifie facilement.

Branches courtes

Fusionnée vite : moins elle s'écarte de main, moins elle entre en conflit.

Une relecture par les preuves

Ce qu'elle annonce, la voir fonctionner, la liste des fichiers : la checklist de revue.

Le conflit est normal

Deux branches touchent le même fichier. On choisit, on efface les marqueurs, on commite.

démonstration courte : deux branches, le même fichier, un conflit, sa résolution · pas à pas : séance 2, chapitre 1

La règle de l'auteur · Simon Willison

Don't file pull requests with code you haven't reviewed yourself

Ne proposez pas de PR avec du code que vous n'avez pas relu vous-même.

avant de demander la relecture : l'avoir vue fonctionner, savoir l'expliquer · « c'est l'agent qui l'a écrit » n'est pas une réponse recevable
